# Shift-left cybersecurity for medical devices

ACI describes work for a Germany-based multinational biomedical-technology company
operating in more than 100 countries. The client needed security validation to keep pace
with Agile medical-device development while meeting strict product-quality, regulatory,
and patient-data requirements.

ACI introduced a three-phase shift-left security-testing program. First, the team mapped
product requirements to cybersecurity controls, designed security tests, automated
suitable cases in the existing functional framework, and integrated them into CI/CD.
Second, it expanded validation through static code inspection and manual testing of
cryptography, Bluetooth security, debugging logs, and code obfuscation. Third, it added
the automated tests to continuous regression so every build received security
validation.

The supplied document reports that more than 50% of cybersecurity test cases were
automated, validation cycles became 40% faster, regression effort fell 35%, issues were
detected 60% earlier in the development lifecycle, and every build received security
validation. The current ACI case-study listing summarizes the outcome as 67% earlier
vulnerability detection. Because the published versions differ, answers should identify
which source version a percentage comes from instead of combining the two.

Technologies and methods include a security-test automation framework, static code
analysis, CI/CD integration, code inspection, manual security testing, and Agile test
management.
